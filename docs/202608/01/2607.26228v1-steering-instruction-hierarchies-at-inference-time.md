## 摘要
指令层级是语言模型部署的核心安全假设：更高优先级的输入（如系统提示）应覆盖来自用户或工具的冲突低优先级输入。然而，前沿LLM经常违反这一层级。我们提出V-Steer，一种无需训练的推理时方法，通过编辑缓存值向量在提示位置恢复特权影响。利用首个下一token预测的直接logit归因，V-Steer识别出低优先级跨度主导特权跨度的注意力头，然后通过对缓存V张量进行原地乘法编辑来增强特权跨度并抑制冲突的低优先级跨度。由于该方法仅作用于缓存的值，它保持与融合注意力后端兼容，并且只增加一次预填充开销。在7B到70B的模型中，这种归因引导的干预在受控角色冲突基准上将主要约束准确率从低于18%提高到92%，并在更广泛的指令层级评估中显著优于仅提示基线，在LLM的4个规模中的3个上匹配或超过基于SoTA训练的方法，且解码速度开销可忽略。代码可在https://github.com/cindy2000sh/v-steer获取。

## Abstract
Instruction hierarchies are a core safety assumption of language model deployment: higher priority inputs, such as system prompts, should override conflicting lower priority inputs from users or tools. Yet frontier LLMs often violate this hierarchy. We introduce V-Steer, a training-free inference time method that restores privileged influence by editing cached value vectors at prompt positions. Using direct logit attribution on the first next token prediction, V-Steer identifies heads where lower priority spans dominate privileged ones, then boosts privileged spans and suppresses conflicting lower priority spans through in-place multiplicative edits to cached V tensors. Since the method acts only on cached values, it remains compatible with fused attention backends and adds only a one time prefill overhead. Across models from 7B to 70B, this attribution guided intervention raises primary constraint accuracy from under 18% up to 92% on controlled role conflict benchmarks, and on broader instruction hierarchy evaluations substantially outperforms prompt only baselines while matching or exceeding SoTA training based methods on 3 of 4 scales of LLMs, with negligible decoding-speed overhead. The code is available at https://github.com/cindy2000sh/v-steer.

## 1. 核心问题与整体含义（研究动机与背景）

指令层级（Instruction Hierarchy, IH）是LLM系统安全可控性的核心机制：系统/开发者消息（高优先级）应覆盖用户请求、对话历史、工具输出等低优先级输入。该假设是GPT-5等前沿模型系统卡中"指挥链"设计的基础，通常通过专门的对齐训练来强化。

**核心矛盾**：前沿LLM在实际部署中频繁违反这一层级——当用户请求或工具输出与系统约束冲突时，模型内部会过度加权低优先级的用户/工具输入，使恶意用户提示注入、代理劫持等攻击突破安全边界。研究表明，仅用提示强调层级顺序（如"你必须永远遵循这个约束"）几乎无效。

**研究缺口**：现有方案要么依赖提示工程（收效甚微），要么需要额外训练（昂贵、不灵活）。缺乏一种**廉价、有效的推理时控制手段**来恢复指令层级。V-Steer正是填补了这一空白——不动模型权重，仅在推理时通过编辑缓存值向量实现层级恢复。

## 2. 方法论：V-Steer

### 2.1 核心思想

V-Steer的出发点是对模型内部计算的归因分析：当指令层级冲突发生时，模型内部某些注意力头（heads）对低优先级跨度的归因贡献超过了高优先级跨度，这些"坏头"是层级违背的内部中介。V-Steer定位这些坏头并直接干预其缓存值向量，从而在不改变注意力计算的前提下改变输出行为。

### 2.2 关键技术：Direct Logit Attribution（DLA）

利用首个next-token预测的**直接logit归因**，将最终logit线性分解为各层、各头、各源位置的贡献：

- 最终残差流 = 嵌入 + Σ注意力残差 + ΣMLP残差
- 注意力残差按头分解：`c(ℓ,y,h,t)` 表示位置t通过层ℓ、头h对token y logit的直接贡献
- 聚合为跨度归因：`φ(ℓ,h,A)` 和 `φ(ℓ,h,B)`，分别表示特权跨度A和低优先级跨度B对logit的总贡献

**坏头判据**：若 `φ(ℓ,h,B) > φ(ℓ,h,A) + ε`，则该头被认定为"偏向低优先级"的坏头。

### 2.3 价值缓存导向（Value-Cache Steering）

核心洞察：注意力输出对值向量是**线性**的。将位置t的值向量乘以缩放因子 `m_t`，效果等价于缩放该位置的有效注意力权重，但**绕过了softmax的非局部耦合**：

```
o(h) = Σ α(h,t) · (m_t · v(h,t)) = Σ (α(h,t) · m_t) · v(h,t)
```

**优势**：
1. **无softmax耦合**：编辑v只改变该位置的贡献，不影响其他位置的归一化
2. **兼容融合注意力**：不修改注意力核，无需物化注意力矩阵，保留FlashAttention/SDPA的快速路径——注意力导向（Attn-Steer）则必须物化注意力矩阵，带来2.4×解码减速
3. **一次性开销**：编辑仅发生在prefill阶段，解码阶段零额外开销

### 2.4 算法流程（文字描述）

1. **Prefill**：对提示执行一次前向传播，获取缓存值向量v、注意力权重α、首个next-token logits
2. **DLA归因**：利用prefill产物计算各头对跨度A和B的归因
3. **坏头筛选**：标记归因B > A + ε的头为坏头
4. **值编辑**：对坏头执行——A跨度值向量乘 `(1+γ₊)` 增强，B跨度值向量乘 `(1-γ₋)` 抑制
5. **解码**：用修改后的KV缓存正常解码，新生成token正常追加

### 2.5 扩展变体

- **V-Simple**：零提取成本的简化版——整段系统消息作为A，整段用户消息作为B
- **V-Auto**：无监督跨度发现——通过KMeans聚类注意力头的注意力模式，自动识别冲突跨度（实验效果不及V-Simple）
- **GQA适配**：通过并集规则将查询头级的坏头判定提升到KV头级

## 6. 主要结论与发现

1. **推理时干预有效**：指令层级的一部分"强制执行"能力可在不修改权重的推理时直接干预中获得——DLA识别的坏头是层级违背的因果中介
2. **价值导向优于注意力导向**：值缓存编辑在准确性和效率上双重超过注意力导向（无2.4×减速、无softmax耦合副作用）
3. **提示基线为何失败**：DLA热图显示，强调性提示（Emph.）并不改变哪些头偏向低优先级跨度——提示无法重塑内部归因
4. **针对性干预优于无差别干预**：全头导向虽略增准确率但生成崩溃率提升14×，DLA头选择实现了精准干预
5. **跨度提取的鲁棒性**：零成本的V-Simple在大多数设置下匹配V-Steer，LLM提取0-shot/1-shot也远超基线
6. **超参宽容度**：性能在γ₊×γ₋宽范围内稳定，但极端γ₊可能因退化输出而非真正遵守层级虚增安全得分
7. **通用能力代价可调**：默认V-Simple在MMLU上损失8.5分，但γ₋降至0.25时损失仅1.9分、IH合规性仍有60.6%（vs 6.8%基线）

## 8. 不足与局限

### 实验覆盖局限
- **工具使用场景是明显短板**：IHEval工具注入/内在工具类别改善微弱甚至下降，该方法对tool-format复杂场景泛化不足
- **70B结果基于INT8量化**：量化对V-Steer效果的影响未分离评估，高精度场景下的表现待验证
- **单GPU环境**：未在多卡推理/真实生产部署（如vLLM批量推理）中验证，工程可落地性评估不完整
- **推理时基准梯队不完整**：未与Thinking Intervention、InstABoost等其他推理时方法在同一基准上对比

### 方法局限
- **依赖跨度标注**：V-Steer需要知道冲突跨度的位置——在真实场景中这需要额外提取步骤或LLM调用，增加了部署复杂度和幻觉风险
- **V-Simple的退化风险**：在复杂场景（如Llama-3.1-8B rich/Task）V-Simple准确率骤降至49.0%，零成本方案并非始终安全
- **V-Auto不达预期**：无监督跨度发现方法在多个场景下明显弱于V-Simple（如34.2 vs 82.9），注意力聚类不足以可靠分离冲突跨度
- **安全类任务改善有限**：安全防御中的提取子任务（11.3→19.4）、工具安全几乎无提升；极端γ₊可导致生成退化，安全性部分源于"输出崩坏"而非真正的层级遵循
- **通用能力损失**：默认设置在MMLU上有−8.5点损失，虽可调但存在"遵循层级 vs 保持能力"的固有张力

### 偏差与公平性风险
- 训练基线可能未针对测试分布优化，与V-Steer的对比存在"针对测试集设计"的不对称风险
- IHEval评估使用贪心解码而Control Illusion用采样，跨基准结果对比需注意条件差异
- 提示+导向的协同（V-Steer+Prompt）在部分类别（如分类99.2 vs 34.1）提升异常显著，可能是特定类别格式敏感性所致
