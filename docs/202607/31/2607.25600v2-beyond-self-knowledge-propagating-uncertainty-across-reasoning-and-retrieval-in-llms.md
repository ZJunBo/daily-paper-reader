## 摘要
检索增强生成改善了知识密集型问答，但不加选择的检索可能引入无关证据和不必要的计算。我们研究了黑盒语言模型口头表达的置信度是否可以作为检索路由的可操作信号。我们的方法BeyondUncertainty首先获取结构化的临时答案和置信度估计，然后在保留验证数据上选择模型特定的阈值，并在测试评估前固定该阈值。低置信度问题接收前5个TF-IDF检索，然后进行第二次答案调用，而高置信度问题直接返回临时答案。我们在六个问答基准、三个模型家族和三种检索策略上评估了27,000个策略实例。BeyondUncertainty实现了0.483的平均词级别F1，而始终检索为0.467，不检索为0.401，同时相对于始终检索将检索段落减少了20.4%。当在每个数据集-模型单元内匹配路由到检索的问题数量时，它在18个设置中的17个中优于事后随机分配，平均增益为0.024 F1。尽管作为绝对概率校准不佳，但探针不确定性适度预测了问题级别的检索收益（AUROC = 0.628）。然而，额外的探针使总令牌使用量增加了28.2%，揭示了更选择性证据获取与端到端令牌效率之间的权衡。

## Abstract
Retrieval-augmented generation improves knowledge-intensive question answering, but indiscriminate retrieval can introduce irrelevant evidence and unnecessary computation. We investigate whether verbalized confidence from black-box language models can serve as an actionable signal for retrieval routing. Our method, BeyondUncertainty, first elicits a structured provisional answer and confidence estimate, then applies a model-specific threshold selected on held-out validation data and frozen before test evaluation. Low-confidence questions receive top-5 TF-IDF retrieval followed by a second answer call, whereas high-confidence questions return the provisional answer directly. We evaluate 27,000 policy instances across six QA benchmarks, three model families, and three retrieval policies. BeyondUncertainty achieves 0.483 mean token-level F1, compared with 0.467 for always retrieval and 0.401 for no retrieval, while reducing retrieved passages by 20.4\% relative to always retrieval. When matched on the number of questions routed to retrieval within each dataset-model cell, it outperforms a post-hoc random allocation in 17 of 18 settings, with an average gain of 0.024 F1. Although poorly calibrated as an absolute probability, probe uncertainty modestly predicts question-level retrieval benefit (AUROC = 0.628). However, the additional probe increases total token usage by 28.2\%, revealing a trade-off between more selective evidence acquisition and end-to-end token efficiency.

## 1. 核心问题与整体含义（研究动机与背景）

- **研究背景**：检索增强生成（RAG）通过引入外部证据来改善知识密集型问答，但**盲目检索并非总是有益**——既会增加上下文长度与推理延迟，还可能引入无关或冲突的段落，反而降低生成质量。
- **核心问题**：对于一个**黑盒 LLM 模型**，能否仅利用模型自身“口头化置信度”这一可观测信号，来决定**哪些问题需要检索、哪些问题可以直接回答**？
- **关键区分**：本文不关注“自我知识”的绝对可靠性，而是追问一个更实际的问题——**黑盒置信度信号能否作为检索路由的可操作决策信号**，并进一步判断它识别的是“**检索后收益更高的问题**”，而不仅仅是“减少检索频率”。

## 2. 方法论

- **核心思想**：采用一个**模型无关的黑盒控制器**，通过结构化的“预检索探针”获取置信度，再根据冻结阈值决定是否触发检索。
- **探针结构**：对每个问题 $q$，模型首先返回可观测状态 $s_0 = (\\hat{a}_0, c_0, d_0, m_0)$，其中：
  - $\\hat{a}_0$：临时答案；
  - $c_0 \\in [0,1]$：口头化置信度；
  - $d_0$：模型建议的检索动作（仅记录，不参与路由决策）；
  - $m_0$：不超过两句话的状态摘要（替代隐藏思维链）。
- **路由规则**：定义不确定性 $u_0 = 1 - c_0$，路由判定为 $\\mathcal{R}(q, m) = \\mathbb{I}[c_0 < \\tau_m]$，其中 $\\tau_m$ 为模型特定阈值，在验证集上选定并**测试前冻结**。缺失或无法解析的置信度保守地路由到检索。
- **决策理论解释**：控制器在检索期望收益 $\\mathbb{E}[Y_1 - Y_0 | c_0, q] > \\lambda C_R$ 时触发检索，其中 $\\lambda$ 编码资源代价权重；置信度阈值是该规则的一种降维近似。
- **执行流程**：
  1. 高置信度问题 → 直接返回临时答案（1 次模型调用）；
  2. 低置信度问题 → 触发确定性 TF–IDF 稀疏检索（top-5 段落）→ 将问题与段落拼接 → 再次调用模型生成最终答案（2 次模型调用）。
- **关键属性**：不依赖隐藏思维链、logits、内部激活、微调等；不需要学习路由参数；使用可复现的固定决策规则。

## 3. 实验设计

- **数据集**：6 个问答基准——Natural Questions (NQ)、HotpotQA、2WikiMultiHopQA、SQuAD、TriviaQA、MuSiQue（同时覆盖单跳与多跳问答）。
- **数据规模**：每个数据集固定选择 500 个测试问题，共 3,000 个独特问题；构建数据集特定的受控检索语料库（去重后的 title–passage 文档规模为 6,299–17,687）。
- **模型家族**：3 个通过同一 OpenAI 兼容端点访问的模型：OpenAI gpt-5.5、Gemini gemini-3.5-flash、Claude claude-sonnet-5。
- **对比策略**：
  - No Retrieval（不检索，直接回答）；
  - Always Retrieve（始终检索 top-5 后回答）；
  - BeyondUncertainty（置信度路由）；
  - Route-count-matched random control（路由数量匹配的随机分配）；
  - Retrospective oracle（事后在两种静态策略结果中取最优）。
- **评估指标**：归一化 token 级 F1（主要指标）、Exact Match、检索段落数、网关报告的 token 使用量、AUROC/AUPRC、ECE-5。
- **统计方法**：18 个数据集-模型单元内进行配对 Wilcoxon 符号秩检验（共 54 组比较），并采用 Holm 校正控制多重检验误差。

## 6. 主要结论与发现

- **置信度的决策效用**（RQ1）：
  - 置信度与最终 F1 正相关（$\\rho = 0.276\\text{–}0.309$），但绝对校准很差（ECE-5 为 0.426–0.528）；
  - 不确定性对检索收益（$\\Delta_{ret} = F1_A - F1_N$）的预测 AUROC = 0.628，AUPRC = 0.447（正例率 35.4%）——具备**适度的序数路由价值，而非概率校准价值**。
- **质量-效率权衡**（RQ2）：
  - BeyondUncertainty 达到最高聚合 F1（0.483），比不检索高 0.082，比始终检索高 0.016；
  - 检索段落减少 20.4%（3.952 vs 4.966/实例）；
  - 但**总 token 用量增加 28.2%**（1539.8 vs 1201.5/实例）——方法是“检索节省型”，**不是“token 节省型”**。
- **分配价值**（RQ3）：在路由问题数量完全匹配的条件下，置信度路由在 18 个单元中的 17 个优于随机分配，平均增益 0.024 F1（唯一例外为 MuSiQue–OpenAI，-$0.001$）；与 Oracle 之间仍有 0.040 的差距，表明预测能力尚存提升空间。
- **模型依赖性**：路由行为高度依赖模型——OpenAI 的检索率高达 98.5%（接近始终检索），Gemini 为 62.8%，Claude 为 75.9%；优势主要体现在路由分布较分散的设置（如 Gemini 的 TriviaQA、NQ）。

## 7. 优点

- **黑盒友好与模型无关**：仅依赖口头化置信度，不要求 logits、内部状态或微调，可适用于异构私有 API。
- **大规模配对评估**：27,000 个策略实例跨 3 个模型家族和 6 个多/单跳数据集，覆盖面广。
- **事后失败保留**：而非事后过滤，降低选择偏差；并验证了失败行不影响主要结论。
- **路由计数匹配的对照设计**：巧妙地将“检索频率效应”与“问题选择效应”分离，验证了置信度的真实分配价值。
- **统计推断谨慎**：使用 Holm 校正并同时报告各单元的显著性差异，避免夸大结论。
- **Oracle 比较量化了改进空间**：0.040 的 gap 为后续研究提供了明确方向。

## 8. 不足与局限

- **绝对置信度校准差**：ECE 超过 0.4，置信度作为概率意义不大，只能用作排序信号。
- **端到端 token 效率不升反降**：额外的置信度探针使总 token 用量增加 28.2%，可能使系统在长问题场景下的实际延迟与成本更高。
- **检索语料受限**：使用受控 TF–IDF 局部语料库（去重 title–passage 对）而非生产级开放维基百科索引，外推到真实开放域检索的结论有限。
- **对照未完全匹配执行路径**：随机匹配控制为事后重组静态输出，未复现置信度控制器的结构化探针和两阶段调用路径，对因果效应估计有影响。
- **单元间显著性差异不均匀**：置信度路由 vs 始终检索在 15/18 个单元中无显著差异，优势更多表现为聚合平均而非稳定优势。
- **网关别名与时间特定性**：模型版本为网关报告的别名（gpt-5.5、gemini-3.5-flash、claude-sonnet-5），无法独立验证其真实模型版本，且 API 行为随供应商更新而可能漂移。
- **多跳复杂度挖掘有限**：未对 MuSiQue 等多跳任务的检索失败机理进一步分析；该数据集失败覆盖率较低（94.4%）可能引入偏倚。
